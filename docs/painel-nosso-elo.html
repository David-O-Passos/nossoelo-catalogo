02 — A arquitetura

Três serviços gratuitos, cada um com um único trabalho

Nenhum deles depende do outro pra funcionar. Se o Google atrasar, o site continua respondendo com os últimos dados que guardou. Se o GitHub atrasar, o catálogo de preços não sente nada — só o envio de fotos novas espera.

Google Sheets

É o banco de dados. Editável de qualquer celular, com histórico de versões — sem aprender nada novo.

GitHub

Guarda as fotos e o código do site. Toda foto nova vira um registro — e dispara o próximo passo sozinho.

Cloudflare Pages

Serve o site pra qualquer lugar do Brasil, rápido, de graça, sem pausa por inatividade.

03 — A rotina mensal

Nem toda atualização é igual

Mudar preço nunca passa pelo GitHub — é direto da planilha pro site. Produto novo com foto passa, sim, mas o deploy acontece sozinho; ninguém precisa tocar no Cloudflare.

04 — A migração

O catálogo antigo não foi digitado de novo à mão

Foi lido, entendido e convertido. O documento original tinha 1.146 fotos soltas e nenhuma lista de produtos — só um layout bonito pra imprimir.

05 — Decisões técnicas

Cada escolha teve um motivo

Geralmente, o motivo foi o mesmo: evitar que o projeto precisasse de alguém pra sempre — inclusive de mim.

sem-banco-de-dados O Google Sheets já é editável, já tem histórico de versões, e ninguém precisa aprender nada novo.
sem-framework HTML, CSS e JavaScript puro. Nada quebra daqui a dois anos porque um npm install parou de funcionar.
sem-servidor-proprio O site é só arquivos estáticos. A única parte "viva" é a função que recebe fotos novas.
carrinho-no-celular O pedido fica guardado no navegador do próprio cliente — só existe de verdade quando ele manda pro WhatsApp.
sem-cache-agressivo De propósito: um site rápido demais que mostra preço velho é pior que um site normal.
